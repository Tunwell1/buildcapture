Build Capture changelog
=======================

1.1.3
-----

Selection
- The box no longer has to be aimed at to be moved. With the face-edit key
  held, the scroll wheel now moves the whole box along your view and Ctrl+scroll
  moves it up or down, matching the placement preview. The arrow keys move it one
  block and Page Up / Page Down cover the vertical axis; Shift gives five-block
  steps. Resizing still drags a face, which is the only unambiguous way to pick a
  side.
- The corner panel shows the selection while the face-edit key is held: size,
  coordinates, the available gestures and the last step ("Moved: up",
  "Resizing: north"). The controls no longer scroll away in the chat.
- New keys: `[` and `]` set the corners, `Enter` opens a save dialog with the
  name pre-filled from the timestamp, so the normal capture flow never opens the
  chat window. All bindings are rebindable.
- Network protocol bumped to 6, so update the client and the server together.

1.1.2
-----

Preview
- The ghost is drawn as a single translucent skin now: a depth-only pass keeps
  the nearest ghost surface, so the world behind the structure shows through
  instead of the far side and the inside of the preview. It reads much more
  like a hologram; solid previews (`capture.previewTranslucent = false`) are
  unchanged.
- The preview block limit is no longer a frame-rate limit. The default is
  raised from 50,000 to 150,000 blocks, which is the practical ceiling for the
  single packet the server sends the block list in. Lower
  `capture.previewMaxBlocks` on weak clients; bigger builds still fall back to
  the footprint box. Existing config files keep their old 50,000 value, so raise
  it by hand (or delete the config) after updating.
- Network protocol bumped to 5, so update the client and the server together.

1.1.1
-----

Preview
- Large placement previews no longer re-tessellate every block model on every
  frame. The ghost is baked into one cached vertex buffer when the structure,
  rotation or the 16-block tint cell changes, and is then re-drawn with a
  translation, which removes the per-frame CPU cost that made builds with tens
  of thousands of blocks lag. Moving the preview one block does not rebuild it.
- New option `capture.previewTranslucent` (default true). Turning it off draws a
  solid preview; it is mostly a look/blending option, since the geometry cost is
  cached either way.

1.1.0
-----

Browser
- New in-game structure browser, opened with the `C` key (rebindable) or
  `/capture gui`. It lists every capture from the world datapack and the shared
  library with its dimensions and file size, has a search box, and marks
  world-only, library-only and mirrored entries with a coloured dot.
- Place from the browser now starts a placement preview: the structure is shown
  as translucent block models at the target spot, with a green footprint box
  (red when it does not fit the build height). Structures above 50,000 blocks or
  1,536 palette entries fall back to the box alone so the preview stays cheap;
  `capture.previewMaxBlocks` lowers the block limit on weak clients. Move it
  with the scroll wheel, `Ctrl`+scroll for the vertical axis, arrow keys for
  single blocks, `R` to rotate; right-click or Enter places it, middle-click or
  Escape cancels. Nothing is written until you confirm, and the server
  re-validates the id, the distance and the build height.
- Import .nbt files without leaving the game: the file dialog or a drag-and-drop
  onto the window. The client uploads the file in 22 KB chunks, and the server
  validates the structure (gzip NBT, `size`, `palette`, `blocks`, per-side limit)
  before writing it to the world datapack and the shared library under a free
  id. A file saved by a newer Minecraft is accepted with a DataVersion warning.
- Delete entries from the browser with a confirmation click; a backup of every
  deleted file is kept.
- Undo button in the browser: reverts your last operation (save, import or
  delete), the same as `/capture undo`, and greys out when there is nothing to
  revert.
- "Open library folder" button for the shared library (client and server on the
  same machine).

Fixes
- The selection is now dropped after a successful `/capture save`, so the box
  no longer stays on screen. Controlled by `capture.clearAfterSave`.
- Placing from the browser is no longer limited to the block in front of the
  player: the preview can be moved and confirmed anywhere within 256 blocks.
- Rotated placements now start at the previewed corner. The rotation offset that
  vanilla structure blocks apply was missing, so 90/180/270 degree placements
  could land beside the ghost instead of under it.

Config
- New option `capture.clearAfterSave` (default true).
- New option `capture.importMaxMb` (default 16, 1-64).
- New option `capture.previewMaxBlocks` (default 50000, 1000-80000) caps how
  large a build the placement preview draws block by block.
- Network protocol bumped to 4; the client and the server must both run 1.1.0.

1.0.0 - first public release
----------------------------

Build Capture is a standalone capture mod. The village decoration features of
the earlier combined project are not part of this jar and live separately.

Capture
- New `/capture` command group: select two corners of any build and save it as a
  datapack structure template, with entities included. The name is free-form
  (`castle/tower` or an existing id such as
  `minecraft:village/plains/houses/plains_small_house_1`), so no catalog of
  known houses is needed.
- Captures are written to `world/datapacks/buildcapture_captures` and can be
  used immediately with `/capture place`, or enabled for structure blocks with
  `/capture reload`.
- Every overwrite is backed up to
  `world/buildcapture_backups/<world|library>/<namespace>/<path>/`; `/capture
  undo` restores the previous version or deletes a newly created capture.
- `/capture list`, `/capture status`, `/capture clear` and `/capture place` for
  inspecting, resetting and re-placing the selection. `/capture place` exists
  because 1.16.5 has no vanilla `/place` command.
- The capture corners are drawn as a translucent box with a through-terrain
  outline, synced from the server to the owning client.
- `/capture expand`, `/capture shrink` and `/capture move` resize one face at a
  time or move the whole box without reselecting the corners. Directions are
  `north`/`south`/`east`/`west`/`up`/`down`, the step defaults to 1 block, and
  the box is kept inside the build height and `capture.maxSize`.
- Interactive editing: hold the face-edit key (left Alt by default) to highlight
  the face under the crosshair, drag it with the left mouse button, hold
  Shift to move the whole box, and scroll for single-block steps. The client
  sends complete bounds; the server clamps them to the build height and
  `capture.maxSize` before echoing them back.
- Faces seen head-on are pushed or pulled by moving the mouse vertically, and
  the box can be edited from inside.
- New config option `capture.maxSize` (default 64 blocks per side).
- New config option `capture.libraryDir`: every capture is also mirrored into a
  shared library outside the world, usable from every save. `/capture place`
  falls back to it and `/capture list` marks library-only entries with `*`.
  Overwritten library entries are backed up like world captures, and
  `/capture undo` restores both copies. The library folder is a valid datapack,
  so it can be copied into a world or shipped inside a mod. `/capture status`
  reports the library folder (or that it is disabled).

Multiplayer
- Vanilla clients can join a server that only has this mod installed; the mod is
  server-side, and only the selection box is unavailable to them.

Technical
- The mod id is `buildcapture`; the package is `com.tunwell.buildcapture`.
- The selection is server-authoritative: the client only sends bounds, the
  server clamps them and echoes the result.
- The output is plain vanilla structure NBT, with no lock-in.
